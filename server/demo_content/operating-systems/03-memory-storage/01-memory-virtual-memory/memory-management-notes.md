# Memory Management: Allocation, Paging and Segmentation — Lecture Notes

CS-304 Operating Systems · Unit 3 · Memory and Storage Management

## 1. Basic Concepts

- A **logical (virtual) address** is generated by the CPU; a **physical address** is the one seen by the memory unit. The **Memory Management Unit (MMU)** maps one to the other at run time.
- With a simple **relocation register**, physical address = logical address + relocation value; a **limit register** holds the size of the process's range, and any logical address >= limit causes a trap (protection fault).
- **Address binding** can happen at compile time (absolute code), load time (relocatable code) or execution time (requires MMU support; used by all modern OSes).
- **Swapping** moves an entire process (or, in modern systems, individual pages) between memory and a backing store.

## 2. Contiguous Memory Allocation

Each process occupies one contiguous block. With **variable partitions**, the OS keeps a list of free **holes** and chooses one for each request:

| Strategy | Rule | Notes |
|---|---|---|
| First fit | Allocate the first hole that is big enough | Fast; generally as good as best fit for utilisation |
| Best fit | Allocate the smallest hole that is big enough | Must search the whole list (unless sorted); leaves tiny leftover holes |
| Worst fit | Allocate the largest hole | Leaves large leftovers; performs worst in simulations |

Example: holes of 100, 500, 200, 300 and 600 KB (in order) and a request for 212 KB. First fit chooses **500 KB**, best fit chooses **300 KB**, worst fit chooses **600 KB**.

## 3. Fragmentation

- **External fragmentation**: enough total free memory exists to satisfy a request, but it is not contiguous. The **50-percent rule**: with first fit, given N allocated blocks, about 0.5N blocks are lost to fragmentation, so roughly **one-third** of memory may be unusable. Remedies: **compaction** (only possible with execution-time binding, and costly) or non-contiguous allocation (paging, segmentation).
- **Internal fragmentation**: memory allocated to a process is slightly larger than requested, and the unused space inside the allocated unit is wasted.

## 4. Paging

Paging removes external fragmentation by dividing physical memory into fixed-size **frames** and logical memory into **pages** of the same size (a power of two, commonly **4 KB**; huge pages of 2 MB or 1 GB also exist).

A logical address of m bits with page size 2^n is split into:

```
| page number p (m - n bits) | page offset d (n bits) |
physical address = frame_number(page_table[p]) * page_size + d
```

### Worked translation

Page size = 1 KB (1024 bytes). Logical address 2500:

- p = 2500 div 1024 = **2**; d = 2500 mod 1024 = **452**.
- If page_table[2] = frame 5, physical address = 5 × 1024 + 452 = **5572**.

### Page table size

A 32-bit address space with 4 KB pages has a 12-bit offset and a 20-bit page number, so the page table has 2^20 = 1,048,576 entries. At 4 bytes per entry this is **4 MB per process**. Solutions: **hierarchical (multi-level) page tables** (two levels of 10 bits each on 32-bit x86; four or five levels on x86-64), **hashed page tables**, and **inverted page tables** (one entry per physical frame).

### Internal fragmentation in paging

Paging has no external fragmentation, but the last page is usually partly empty. Example: page size 2048 bytes and a process of 72,766 bytes. 72,766 = 35 × 2048 + 1086, so the process needs **36 frames** and wastes 2048 − 1086 = **962 bytes**. On average half a page per process is wasted, which argues for small pages; large pages give smaller page tables and more efficient I/O.

### Page-table entry bits

Besides the frame number, a PTE contains a **valid/invalid** bit, **protection** bits (read/write/execute), a **dirty (modified)** bit, a **reference (accessed)** bit and caching controls.

## 5. Translation Lookaside Buffer (TLB)

Storing the page table in memory means every data access needs **two** memory accesses: one for the PTE and one for the data. The **TLB** is a small, fast, associative cache of recent page-to-frame translations, typically 32 to 1024 entries.

- **TLB hit**: frame number obtained directly.
- **TLB miss**: read the PTE from memory, then insert it into the TLB (replacing an entry, often LRU).
- **ASIDs** (address-space identifiers) let TLB entries from several processes coexist; without them, the TLB must be flushed on each context switch.
- **Hit ratio** α is the fraction of references found in the TLB.

### Effective access time (EAT)

With TLB lookup time ε, memory access time m and hit ratio α:

```
EAT = α (ε + m) + (1 - α) (ε + 2m)
```

Example: m = 100 ns, ε = 20 ns.

- α = 0.80: EAT = 0.80 × 120 + 0.20 × 220 = 96 + 44 = **140 ns** (a 40% slowdown over 100 ns).
- α = 0.98: EAT = 0.98 × 120 + 0.02 × 220 = 117.6 + 4.4 = **122 ns** (22% slowdown).

If the TLB lookup time is treated as negligible (as in many modern texts), EAT = α m + (1 − α) 2m; with m = 10 ns and α = 0.99, EAT = 9.9 + 0.2 = **10.1 ns**.

With a two-level page table and no TLB hit, a reference needs three memory accesses, so the miss term becomes (ε + 3m).

## 6. Segmentation

Segmentation supports the programmer's view of memory as a collection of variable-sized **segments** (code, global data, heap, stack, each library). A logical address is the pair **<segment-number, offset>**.

The **segment table** holds a **base** (starting physical address) and a **limit** (length) for each segment. If offset >= limit, the hardware traps; otherwise physical address = base + offset.

| Segment | Base | Limit |
|---|---|---|
| 0 | 1400 | 1000 |
| 1 | 6300 | 400 |
| 2 | 4300 | 400 |

- <2, 53> → 4300 + 53 = **4353**.
- <0, 852> → 1400 + 852 = **2252**.
- <1, 500> → 500 >= 400, so **trap** (addressing error).

### Paging versus segmentation

| Aspect | Paging | Segmentation |
|---|---|---|
| Unit size | Fixed (page) | Variable (segment) |
| Visible to programmer | No | Yes (logical units) |
| External fragmentation | None | Yes |
| Internal fragmentation | Yes (last page) | None |
| Protection and sharing | Per page | Natural per logical unit |

Intel IA-32 combined both (segmentation followed by paging); x86-64 largely disables segmentation and relies on paging.

## 7. Key Formulas

- Number of pages = 2^(logical address bits − offset bits).
- Page table size = number of pages × PTE size.
- EAT with TLB = α(ε + m) + (1 − α)(ε + 2m).
- Segmentation: physical = base + offset, valid only if offset < limit.
