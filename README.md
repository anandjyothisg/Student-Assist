# AuraStudy (StudentAssist)

AuraStudy is a study assistant for university courses. Teachers organise course material into units and topics, students read it and ask questions, and every answer is generated by a local language model **only from the course documents**, with numbered citations back to the page it came from. Administrators manage people, the course catalog and platform health.

- **Web app:** React 19 + Vite + Tailwind (`client/`)
- **API:** Django 5 + Django REST Framework + JWT (`server/`)
- **AI:** local [Ollama](https://ollama.com) (`llama3.2`), `BAAI/bge-small-en-v1.5` embeddings, ChromaDB vector store

## Quick start (Windows)

```powershell
.\scripts\start-demo.ps1          # first run builds the demo data (a few minutes)
.\scripts\start-demo.ps1 -Reset   # rebuild the demo from scratch (old data is backed up)
```

The script starts Ollama, applies migrations, seeds the demo environment if needed, then opens the API on <http://localhost:8000> and the web app on <http://localhost:5173>.

## Manual setup (any OS)

Prerequisites: Python 3.12, Node 20+, Ollama.

```bash
# 1. Language model
ollama pull llama3.2
ollama serve                         # leave running

# 2. API
cd server
python -m venv .venv
.venv/bin/pip install -r requirements/dev.txt      # Windows: .venv\Scripts\pip
cp .env.example .env                               # set DJANGO_SECRET_KEY
cd src
../.venv/bin/python manage.py migrate
../.venv/bin/python manage.py seed_demo            # demo data (add --reset to rebuild)
../.venv/bin/python manage.py runserver 8000

# 3. Web app (new terminal)
cd client
npm install
npm run dev                                        # http://localhost:5173
```

Redis and a Celery worker are optional. Without them, uploaded documents are indexed in a background thread inside the API process (`DOCUMENT_PROCESSING_MODE=auto`).

## Demo data

`seed_demo` builds everything through the real models and pipelines:

- **2 subjects:** Artificial Intelligence & Data Science, Core Computer Science.
- **6 courses, each structured as 3 units → 2 topics → documents:** AI-301 Artificial Intelligence, ML-302 Machine Learning, CS-201 Data Structures & Algorithms, CS-304 Operating Systems, CS-305 Database Management Systems, CS-308 Computer Networks.
- **52 documents:** authored as Markdown in `server/demo_content/<course>/<unit>/<topic>/`, rendered to real PDF, DOCX and TXT files, then extracted, chunked, embedded and indexed. One topic (OS · File Systems) is intentionally empty.
- **People:** 1 admin, 4 teachers (with designations) and 24 students (programme, year, student number), enrolled across courses.
- **History:** about 40 questions run through the actual RAG pipeline and backdated over three weeks, including out-of-scope questions that are correctly refused. Saved answers and flashcard decks are generated by the model.

Useful commands:

```bash
python manage.py seed_demo --reset --yes            # wipe + rebuild (backs up DB, vectors, files to server/backups/)
python manage.py seed_demo --refresh-history        # regenerate only conversations/flashcards
python manage.py seed_demo --no-history --no-flashcards   # no LLM needed
python manage.py index_documents [--all]            # (re)index pending/failed or all documents
```

## How the assistant works

1. **Scope.** Students search only the published courses they are enrolled in, teachers search the courses they teach, and admins search everything. A question can target one course or all accessible courses.
2. **Retrieval** is hybrid. Dense vector search runs per course in ChromaDB (cosine, BGE query instruction) and the results are merged with an exact keyword pass over stored passages. Superseded and unindexed documents are filtered out. Follow-up questions are searched together with the previous question.
3. **Grounding guard.** If nothing relevant is retrieved, or fewer than 60% of the question's key terms appear in the retrieved passages, the assistant answers *"I couldn't find this in your course materials"* without calling the model.
4. **Generation.** `llama3.2` is prompted to answer only from the numbered excerpts and to cite them as `[n]`. Answers stream token by token over server-sent events (`POST /api/chat/ask/stream/`).
5. **Model unavailable.** If Ollama is not running, the assistant says so and shows the matching passages instead of inventing an answer.
6. **Persistence.** Conversations, citations and answer status (answered / not found / model unavailable) are stored per user. Teacher and admin **Insights** are computed from these records.

## Roles at a glance

| | Student | Teacher | Admin |
|---|---|---|---|
| Ask the assistant | enrolled courses | own courses | all courses |
| Read materials | enrolled courses | own courses | all |
| Upload, structure and publish courses | — | own courses | all |
| Course roster and insights | — | own courses | all |
| Users, roles, subjects and teacher assignment | — | — | ✓ |

These rules are enforced by the API (see `server/src/apps/core/tests/test_demo_permissions.py`), not just by the UI.

## Tests and checks

```bash
cd server/src && ../.venv/Scripts/python -m pytest      # 80+ tests: permissions, security regressions, RAG guards,
                                                        # ingestion/version lifecycle, query budgets
cd server/src && ../.venv/Scripts/python manage.py rag_eval [--llm]   # assistant evaluation with fixed thresholds
cd client && npm run lint && npm run build
```

End-to-end suites (need the API on :8000 and the web app running; set `E2E_APP` if it isn't on :5173):

```bash
cd client
npm run e2e:routing        # landing ↔ auth ↔ app routing, desktop and phone
npm run e2e:acceptance     # role journeys across student, teacher and admin
node e2e/document-lifecycle.cjs   # upload → ready → answer → new version → delete, bad uploads
node e2e/permission-probes.cjs    # live authorization probes
node e2e/keyboard.cjs             # focus visibility and accessible names
node e2e/api-latency.cjs          # endpoint timings
node e2e/landing-perf.cjs 4       # landing page on a 4x throttled CPU
npm run e2e:landing        # landing screenshots, 6 widths × 2 themes
npm run e2e:screens        # every role screen, 6 widths × 2 themes
```
